# 所有紫鸟店铺业务技能的统一登录前置

适用于现在和今后开发的**所有紫鸟店铺网页业务技能**，不限于 IEN 填写和超时货件核查，也包括报告下载、库存、广告、优惠券、订单、沃尔玛、TikTok 等店铺后台流程。调用是同一 Agent 的技能切换，不启动第二个浏览器执行者；登录完成后交还原业务技能。登录、ziniao-store/page/shared 等基础能力不递归调用本前置；纯服务端账号/员工等管理 API 使用各自认证，不凭空打开网站登录。

## 统一入口与授权

- 任何需要访问目标店铺网页的业务执行，**先调用 `ziniao-store-login`，以 `entryMode=ensure_session` 检查并确保目标网站登录态，再进入业务步骤**。这是 Agent 交接模式，不是 CLI flag。已登录且身份匹配则直接返回，不重复提交、不发登录成功通知或索码消息。
- 仅解析/打开浏览器、执行配置诊断、编写技能或补发已有结果且不访问业务网页时，不为此额外触发网站登录。不能把未打开浏览器或未登录的网站登录页误判为已登录。
- 首次发现登录页、二次验证或业务执行中认证失效，先保存业务断点并标记 `blocked_login`，恢复同一个登录前置。白页、Bridge 断开、代理/网络错误先诊断，不能直接当作未登录或循环发码。
- 用户已授权本登录技能作为当前及未来所有上述业务技能的公共前置。常规业务执行可进行目标店铺正常 UI 登录、按固定 XLS 索码并向任务用户同步，不需每次另外要求用户发登录命令。业务结果卡片/附件的按需发送规则仅约束业务结果，不禁止这项已授权的登录协作。
- 当次明确“只读”或“不登录”时，不提交登录、不输入验证码，也不主动索码；仅只读预检后返回阻塞。明确“不发送”时，不发送登录提醒、验证码请求或登录通知；若未禁止登录，可仅尝试已有自动填充 UI 登录，需要人工码则暂停。原任务业务操作、来源表只读和发送范围限制原样继承。
- 登录相关消息仅给固定 XLS 中匹配的验证码联系人，以及本次任务用户。业务卡片/附件的其他收件人不自动成为验证码或登录通知收件人。

## 交接字段

| 字段 | 内容 |
|---|---|
| `entryMode` | 业务前置固定 `ensure_session`；用户单独请求登录则 `login` |
| `parentSkill` | 当前调用方的真实技能名；不限固定列表 |
| `parentBatchId/checkpointPath` | 原业务批次和断点路径；不创建替代原批次 |
| `resumeAt` | 当前阶段、货件或最后完整页/游标等恢复位置 |
| `storeId/storeName/targetId/terminal` | 实际店铺完整名称、ID、页面、同一远程终端；未知ID由登录技能按店铺名解析，页面失效时重取 |
| `expectedSeller/expectedSite` | 已核实的卖家和站点；未知明确记未知，不从其他账号复制 |
| `purpose` | 真实任务用途，例如“用于登录店铺，继续完成 IEN 填写”“用于登录店铺，继续核查超时货件”“用于登录店铺，继续下载上月交易报告”；不可捏造流程 |
| `reportUserOpenId` | 本次任务用户的真实open_id，不是业务结果全部收件人 |
| `restrictions` | 当次只读、不登录、不发送及业务操作/发送范围限制 |
| `loginAttemptId/loginCheckpointPath` | 已有登录子任务传原值，首次才创建 |

上述字段是 Agent 上下文，不是新增 CLI 参数。调用方加载登录技能和本契约，已有 store-id/页面直接复用；不重复开店。验证码联系人始终只读 `D:\共享\验证码请求飞书.xls`，不使用 IEN 来源表、货件负责人或业务收件人替代。

## 登录技能负责的范围

1. 只读检查目标账号与网站身份。`ensure_session` 模式下已登录即安静返回 `already_logged_in`，不为了前置再索码或登录。
2. 确认未登录且允许发送时，以 `--as bot` 给任务用户发一次提醒：“店铺：<完整店铺名>\n用途：<实际用途>\n状态：未登录，正在尝试恢复登录。” 保存幂等键和回执，同次阻塞不重复提醒；有旧提醒回执时复用通知记录。
3. 按主技能尝试自动填充与 UI 提交；必要时按表询问验证码，最多等待原始 5 分钟窗口。询问、相关回复、每次尝试及失败由登录技能统一同步，调用方不另发索码或重复登录提醒。
4. 对外消息只说明完整店铺名和实际用途，不添加站点/请求编号；内部核对账号、站点和 attemptId。临时码不进入任何业务断点。
5. 返回真实状态和页面身份，不执行调用方的业务写入，不发送业务卡片/附件，不改变原批次。

## 返回、恢复与重试

返回 `status`、内部 `attemptId/loginCheckpointPath`（未发生登录时可为空）、当前 `storeId/targetId/terminal`、实际账号/站点及核对时间、`reason`、通知状态/消息ID。通知状态与登录状态独立，原文和验证码不返回业务断点。

- **`verified` / `already_logged_in`**：调用方重新只读核对同一店铺、账号与站点，再进入原业务页面并核对内容。清除旧 selector/snapshot ref，保留原批次，从原阶段恢复。登录已核对而通知失败可恢复业务，通知单独补发，不宣称已通知成功。
- **等待中**：只恢复同一 attempt、联系人、原消息ID和原截止时间，不重新等五分钟、不重复询问。
- **其余状态**（超时、接收失败、联系人缺失、凭据缺失、挑战过期、登录失败/未知、身份不符、权限限制或连接未知）：业务保持 `blocked_login` 并保存 `login.status/reason`，不执行业务步骤，不把 CLI 退出码或人员回复当登录成功。原尝试终止后，不因循环重入再索码；用户明确重试或页面恢复的证据出现后再推进。
- 运行中认证失效同样返回本前置；禁止业务技能自行另写一套登录/验证码逻辑。登录前置不反向调用业务技能，防止递归。

## 新技能编写要求

所有新建或修改的店铺网页业务技能，在正文业务步骤前加入以下条款。即使使用 ziniao-skill-maker 原模板或其他模板，也必须补齐，不能仅写“需要登录”。无需修改 CLI 自带基础技能。

> **REQUIRED SUB-SKILL：ziniao-store-login。** 每次执行店铺网页业务前，先加载该技能及其 `references/upstream-contract.md`，以 `entryMode=ensure_session` 传入目标店铺、真实用途、原任务/断点和当次限制。仅返回 verified/already_logged_in 且重新核对目标身份后进入业务；已登录直接复用，未登录由公共登录技能统一处理。中途失效仍回到同一前置，失败保留断点，不重复索码。业务结果发送范围保持原规则。

规范 Skill 将前置作为步骤 0；Skill+Runtime 也必须在业务动作前取得可验证的目标登录结果，未取得时停止业务，不以进程 exit 0 代替。首次仅探索页面时也先确保目标登录，explore 不允许跳过身份验证；不得因此跳过原 Runtime 的执行验证门槛。

## 当前业务恢复示例

- **IEN**：保留 `save_unknown/saved_unverified/verified` 等业务状态；恢复后按原规则重新打开核对，不重复保存、不覆盖冲突值、不提前标已填写。本批结果卡片 message_id 与幂等键继续使用。
- **货件核查**：保留批次日期/时区、最后完整页游标、已读唯一货件集合和地址/候选证据；登录页不是数据页或末页，恢复后按原分页与去重规则续读。登录成功不代表全量完成。
- **其他业务**：调用方保留每项提交/保存/下载是否已完成的证据；恢复先核对原动作结果，不因重新登录重复提交。
- **旧通知**：历史 `loginReminder` 可保留以防重复；新的登录通知归登录子任务，业务结果仍由调用方按原授权发送。

本契约为通用编排规范；创建或验证规则不执行真实登录、不发送测试消息。
