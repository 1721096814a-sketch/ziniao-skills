# 亚马逊 IEN 填写与飞书结果卡片

输入：店铺、货件范围、钉钉表格链接；已有经过核对的填写结果也可直接进入通知阶段。当前会话没有目标时先解析，不固定任何店铺 ID、账号、货件、IEN、飞书用户或旧消息 ID。

## 权限与工具

- 紫鸟使用 ziniao-store / ziniao-page；钉钉电子表格使用 dingtalk-misc 的 Sheet 规则；飞书通过 lark-cli 的 lark-im 与 lark-shared 当前指南。
- 表格始终只读。用户只要求查询时不填写、不发送业务结果卡片；登录前置与登录协作通知按第0节。用户当次明确只读/不登录/不发送时将限制原样传给前置，不进行相应写操作。用户要求填写时，本批处理结果默认通过精简飞书卡片汇报，查询不到 IEN、来源 IEN 为空的货件也必须发送，即使本批没有成功填写项。
- 紫鸟只读接口串行，响应后间隔 1–3 秒；修改只用 `page input` / `page click` 可信交互。`page exec` 仅检查 DOM 或做只读查询，不改值、不 `.click()`、不拼写接口。iframe/Shadow DOM 无法定位则说明阻塞，不绕过。
- 一个主执行者独占紫鸟标签页。用户授权子 agent 时，子 agent 只做独立查询或本地核对；亚马逊请求节奏不变。

## 0. 店铺登录预检

**只预检目标店铺是否登录亚马逊。用户已确保飞书可用，不额外检查飞书或钉钉登录，不在启动时发起 OAuth。** 只读取当前页面，不为测试登录创建或修改业务数据。

1. **REQUIRED SUB-SKILL：ziniao-store-login。** 需要访问业务网页时，先使用该技能，读取 `../ziniao-store-login/references/upstream-contract.md`，以内部 `entryMode=ensure_session` 检查并确保目标店铺已登录。传入完整店铺名、已知 store-id/target-id/终端、预期卖家/站点、本批ID及断点、当前票/阶段、任务用户、当次限制；已登录则直接复用，不重复登录或索码。仅补发已核对结果时不为此触发登录。
2. 原用途传“用于登录店铺，继续完成 IEN 填写”；仅核查时传真实“IEN 信息核查”用途。出现登录页、重新验证、验证码或中途失效，先保存原业务状态并标 `blocked_login`，由同一登录前置统一提醒、UI尝试、按登录技能内置的 `assets/验证码请求飞书.xls` 联系人员、等待最多5分钟并向任务用户同步。本技能不另发重复索码或登录提醒，不能把 IEN 来源表当验证码联系人表。
3. 登录通知使用 `--as bot`，收件人沿用本批已核实的任务用户；缺少时只解析当前用户身份，不额外登录预检或OAuth。站点/请求编号不出现在对外询问中，保留真实用途。明确只读/不登录时仅预检；明确不发送时不发索码或通知，允许的自动填充路径仍可尝试，需人工码则暂停。
4. 只有前置返回 `verified/already_logged_in`，且本技能重新只读核对相同店铺、卖家、站点与管理货件内容后，才进入或恢复业务。超时、失败、身份不符或未知均保持 `blocked_login`，保存 `login` 子状态；重入恢复同一 attempt 与原截止，不自动新建一轮。不能用HTTP200、浏览器已打开、CLI退出码或用户口头已登录代替核对。
5. 恢复保留原批次、货件范围、卡片ID、每票保存与核对状态，清除旧页面定位。`save_unknown/saved_unverified` 先按第2.1节重新打开只读核对，不因登录恢复重复保存。原登录子任务的通知单独去重与补发，不能把登录成功标成 IEN 已填写。

页面空白、Bridge 断开、网络超时不等于未登录：按紫鸟诊断规则确认原因，未确认前标记“连接/状态未知”，不要发送“未登录”的错误结论。实际钉钉读取或飞书发送若报权限、认证错误，按对应工具指南处理并保存断点；不把这些错误扩展成三端登录预检，不切换账号碰运气。

## 1. 只读匹配

默认使用用户已确认、授权内置于私人技能的 IEN 来源表：
https://alidocs.dingtalk.com/spreadsheetv2/aq1V9O9VF91K8KLW/edit?docKey=Pd6l2YR6YJGyO7Ma&dentryKey=aq1V9O9VF91K8KLW&type=s

用户当次明确指定其他来源时按其指令处理。来源表始终只读；内置链接不代表已获得该文档的访问权限，读取失败时保留断点并报告。

先确认工作表和表头，再读取完整必要范围，检查 returnedRange、hasMore、truncationReasons。保留真实行号；CSV 的 `[row=N]` 是定位前缀，使用 CSV 解析器且保留末尾空行。

账号数字 x 对应「x号机欧洲」。以 **店铺账号＋完整 FBA 货件编号** 唯一匹配 IEN；单元格含多个货件时按完整编号拆分，不做子串或顺序匹配。已知主表名「25年发货记录」，曾为 B=账号、H=货件编码、M=IEN，必须现场确认。

同一账号货件存在多个不同 IEN、账号不明：列为待核查，不填写。完整查询后未匹配到账号＋货件记录，记为 `no_source_match`；匹配到记录但 IEN 为空，记为 `no_ien`。这两类均不填写，但必须加入本批飞书卡片；查询报错、范围截断、尚未查完不能记为“未查询到”。不同货件允许共用同一来源 IEN。转运单号、追踪编码、MRN、EORI 不能代替 IEN。

## 2. 页面填写

1. 核实紫鸟店铺、卖家及站点，定位目标货件。只处理同时满足“页面显示进口详情不全”和“来源 IEN 唯一非空”的货件；默认沿用当前任务范围，不擅自扩展到其他店铺或已完成货件。
2. 点击该行「进口详情不全」，核实侧栏货件编号。在「此货件是否有进口备案记录？」选择「是」，读取出现的 IEN 输入框。
3. 已有值与来源不同：暂停该票，报告冲突；值相同不重复提交。空值用 UI 输入，提交前读回核对货件、选项和 IEN。
4. 点击一次「保存」，等待侧栏关闭、该行缺失提示消失。用条件等待处理异步状态，不用单个固定延迟判定失败。
5. 通过目标行 Actions →「编辑进口申报详情」重新打开，确认「是」仍选中且 IEN 与来源逐字一致，然后「取消」关闭，不重复保存。已核对才记成功。

曾观察到稳定行定位 `[data-row-id="<FBA>"][data-column-id="orderStatus"]`、`actions`；搜索框 placeholder 为「按货件编号搜索」。动态 DOM ID 现场读取，不复用旧 ID。CLI 的交互确认可能在 stderr；同时检查退出码、stdout/stderr、可信点击及页面结果。DOM 读取将结果包成 JSON 对象，避免裸字符串/Promise objectId。

## 2.1 本地检查点与断点恢复

每批在任务目录保存 `ien-run-state/<batchId>.json`。开始时创建，在每次保存/发送前及结果确认后更新；恢复时读取同一检查点，不重新生成批次或幂等键。检查点是恢复线索，页面当前值才是业务事实。

最小字段：
- `batchId`、更新时间、真实 `storeId`、店铺名、卖家和站点。
- 来源表格链接、工作表 ID、账号、货件编号、源行号、来源 IEN。
- `items`：每票目标 IEN、状态、最近观察的页面 IEN、核对时间和错误。
- `notification`：已确认收件人、`as=bot`、本批发送幂等键、状态和 message_id。
- `login`：统一登录前置的 attemptId、子断点路径、真实用途、恢复阶段、状态/原因和原截止时间引用；不复制验证码或消息正文。
- `loginReminder`：旧版阻塞提醒幂等键、状态和 message_id 仅保留用于去重；新登录通知由 `login` 子任务统一维护。

不记录密码、Cookie、验证码、access token、refresh token、应用密钥；不把整个检查点发给飞书。

| 中断时状态 | 恢复动作 |
|---|---|
| `blocked_login` 店铺未登录 | 恢复同一 `ziniao-store-login` 前置/attempt 与原截止时间；失败不自动重发索码。前置成功或用户自行恢复后仍重新核对身份，清除旧页面定位，按原每票状态续做 |
| `pending` / 已输入未提交 | 重新匹配来源并读取页面。IEN 仍为空且匹配唯一，才继续输入和提交 |
| `save_unknown` / `saved_unverified` | 先确认原命令是否仍运行，再重新打开该货件进口详情只读核对。已有值和“是”一致，转为 `verified`；空值且原命令已结束，才允许重新提交；不同值转 `conflict`，不覆盖 |
| `verified` 已填写并核对 | 不重复填写或点击保存。继续其他未完成货件，或仅补发本批卡片；恢复填写任务时先只读确认已完成项仍一致，发生变化则报告冲突 |
| `no_source_match` / `no_ien` | 按真实原因加入本批结果卡片；没有成功项也发送。后来补齐来源并完成填写核对时，更新同一张卡片 |
| 飞书 `pending` / 明确发送失败 / `not_sent_no_verified_items` | 保留已核实的货件结果，只恢复通知阶段；旧检查点因“没有成功项”未发送的，也按当前规则补发本批卡片 |
| 飞书 `send_unknown` | 先查原回执、message_id 或目标会话，确认是否已发送；原调用结束且确认未送达时才用同一幂等键重试。超过工具幂等有效期且发送结果仍未知时暂停核查，不换键盲发 |
| 已有本批卡片 message_id | 只在需更正本批内容时 patch 原卡，不重复发新卡，不更新其他批次 |

点击「保存」前先记 `save_unknown`；保存响应成功仍记 `saved_unverified`；只有重新打开核对一致才记 `verified`。发送前先记 `send_unknown`，拿到成功回执记录 message_id 和 `sent`；卡片内容回读通过另记 `content_verified`。业务填写状态与通知状态分开维护。

若来源 IEN、账号、店铺或收件人与检查点不一致，先核实差异，不把旧批次进度套到新目标。不得把命令超时等同失败，也不得把一次成功响应等同核对完成。

## 3. 精简飞书卡片

**固定格式：标题仅店铺名；表格仅三列「货件编号｜IEN｜填写状态」。** 成功状态固定「已填写并核对」。每店铺单独一张，卡片无称呼、来源、时间、物流、操作说明、统计或按钮。

本批结果卡片必须同时包含成功记录，以及完整查询后确认未匹配到来源或来源 IEN 为空的记录。只有未查到的记录、没有成功项时，也发送非空结果卡片。状态和 IEN 列按下表填写：

| 检查点状态与依据 | IEN 列 | 填写状态 |
|---|---|---|
| `verified`：保存后重新打开核对一致 | 已核对的真实 IEN | 已填写并核对 |
| `no_source_match`：完整查询后没有账号＋完整货件号匹配 | — | 未填写：未查询到 IEN |
| `no_ien`：匹配到来源记录但 IEN 为空 | — | 未填写：来源 IEN 为空 |

未核对、保存失败、冲突项仍在会话中简短说明，不伪装成功。没有上述任何可汇报记录时才不发送空卡片。未查询到 IEN 不等于豁免进口申报，不选择“否”、不编造 IEN、不提交亚马逊。卡片构造器只校验输入形状，不能代替真实页面核对或来源完整性检查。

发送前按 `lark-cli skills read lark-im/references/card/lark-im-card-create.md` 的当前工作流检查 Card 2.0；本技能脚本使用本次已验证的三列表格结构。用 `lark-cli whoami` 确认当前用户，收件人和身份来自真实结果；不拿用户邮箱猜 ID。默认应用私信给当前用户，不发群。

输入文件结构：
```json
{"store":"2号机欧洲","rows":[{"shipment":"FBA15EXAMPLE","ien":"26GBEXAMPLE00000AR1","status":"已填写并核对"},{"shipment":"FBA15EXAMPLE02","ien":"","status":"未填写：未查询到 IEN"}]}
```
示例不是真实可填写或发送的数据。成功记录必须来自页面保存后重新打开核对；未查询到或来源为空的记录必须来自已完成的来源查询。后两类输入 `ien` 传空字符串，构造器在卡片中显示“—”，不传猜测值或其他编号。

生成 JSON（本地生成，不发送）：
```bash
node "<本技能目录>/scripts/ien-card.cjs" results.json
```
把输出作为 stdin 交给 `lark-cli im +messages-send --as bot --user-id <当前用户openId> --msg-type interactive --content - --idempotency-key <本批唯一键>`。保留返回 message_id，并检查 ok=true；超时先查原消息，不能立即换幂等键重发。

用户只要求给本批卡片加字段/改状态：更新同一张卡片。生成 patch 请求体：
```bash
node "<本技能目录>/scripts/ien-card.cjs" results.json --patch <本批真实message_id>
```
将结果交给 `lark-cli im messages patch --as bot --message-id <同一ID> --data -`。新批次发送新卡片，不覆盖历史批次。发送失败与填写失败分别汇报；不能把飞书发送成功当作 IEN 已保存。

发送或更新后，用 `lark-cli im +messages-mget` 回读本批 message_id（参数按当前 help/schema），核对消息类型、店铺及三列内容。接口未返回完整卡片内容时，只说明接口已成功，不宣称卡片内容已回读验证。

验证构造器：
```bash
node "<本技能目录>/ien-card.test.cjs"
```
